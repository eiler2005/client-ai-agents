## Первые улучшения

### 1. Заголовок должен содержать решение по этому проекту

Сейчас второй слайд говорит: «Масштабирование требует эффекта, качества и контроля».
Это подходит для объяснения методики. В клиентской оценке полезнее конкретный
вывод: «До расширения пилота нужно закрыть доступ к данным и встроить эвалы».
Ниже — наблюдения, которые подтверждают этот вывод. Формулировка выводится из
оценки, а не назначается шаблоном. Такой порядок соответствует подаче результатов
в [McKinsey State of AI 2026](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai).

### 2. Сделать слайд «доказательство + последствие + действие»

Слева — основной график, наблюдение или короткая схема. Справа — два-три
предложения: что это меняет, что сделать, по какому признаку принять результат.
Например, в нашем вымышленном банковском проекте: широкие права технической учётной
записи → риск доступа к данным другого клиента → ограничить доступ правами клиента
и подтвердить отказ тестом. Это наша рекомендация по адаптации проблемной подачи
[Bain Technology Report 2026](https://www.bain.com/insights/topics/technology-report/).

### 3. Уменьшить число рамок и цветных подложек

В эталоне три колонки подходят для методики. Для аналитики предлагаю более
свободную композицию: заголовок, тонкий разделитель, график и один акцентный вывод.
На обычных страницах не повторять круги обложки и три карточки автоматически.
Это проектное решение для нашего стиля, а не правило, приписываемое консультантам.

### 4. Приоритеты сделать видимыми в самих данных

Оранжевый выделяет предмет текущего обсуждения или рекомендуемое действие.
Остальные сравниваемые данные — тёмно-синие или серые. Красный нужен только для
подтверждённого блокера или критического риска. Не смешивать цвет бренда с сигналом
опасности; рядом с цветом оставлять текстовое обозначение.

Для карты зрелости — горизонтальные полосы 0–4, полные названия измерений,
явная пометка неоценённого. Необязательно повторять уровень и название во второй
легенде. Уверенность и количество источников можно поместить справа от каждой строки.

### 5. Показывать сравнение «сейчас / следующий этап»

Когда целевой уровень согласован и записан в данных, соединить два значения линией
или поставить их рядом. Это нагляднее двух отдельных таблиц. Без зафиксированной
цели показывать только текущее состояние: шаблон не должен придумывать целевую
зрелость. Идея адаптирует сравнения периодов и групп в
[BCG AI Radar 2026](https://web-assets.bcg.com/73/8e/cc44cbc14a3b81695f8a3de28ff1/ai-radar-2026-web-jan-2026-edit.pdf).

### 6. Чередовать композиции по задаче

Тёмный фон оставить титулу и крупным разделам; светлый — основной аналитике.
Сводку, доказательство, сравнение и план строить по-разному, сохраняя поля,
типографику и цвета. Повторяемость системы важнее повторяемости одной сетки.
Для более строгого варианта можно уменьшить скругления, убрать номер страницы
из плашки и сделать верхнюю полосу тоньше. Текущий v1 сохраняется отдельным эталоном.

## Библиотека следующих композиций

| Приоритет | Композиция | Данные из нашей методики |
|---|---|---|
| 1 | Решение для руководителя: один вывод, 2–3 основания, ближайший шаг | Вердикт, балл, охват, блокеры, highlights |
| 1 | Доказательство слева, последствия и рекомендация справа | finding, evidence, recommendation |
| 1 | Карта зрелости с непосредственными подписями | Уровни 0–4, confidence, неоценённые измерения |
| 2 | Обоснование экономического эффекта | Факт и цель метрик; измеренные объёмы и стоимость |
| 2 | План по этапам с условиями перехода | Этапы КП, сроки, deliverables, gate, роли |
| 2 | Архитектура и границы контроля | Инструменты, данные, права, точка передачи человеку |
| 3 | Выбор между вариантами | Согласованные критерии и варианты решения |

Экономику показывать waterfall-графиком только при наличии действительно
складываемых компонентов одной величины. Иначе использовать обычное сравнение
или диапазон сценариев с явными допущениями. Радар остаётся дополнительным
представлением; для обсуждения конкретных пробелов предпочтительнее полосы.

## Как улучшить два текущих слайда

**Обложка.** Сохранить фон и логотип как узнаваемую композицию; круги эталона v1
заменять предметным визуалом конкретного проекта по принятому стандарту. Крупный
заголовок ограничить тремя строками. Для клиентского выпуска использовать название
задачи, а ниже — тип материала и дату. Длинный подзаголовок сократить до одной мысли.

**Три условия.** Сохранить для объяснения методики или сравнения трёх направлений.
Для оценки конкретного проекта вместо одинаковых общих формулировок показать
статус каждого направления и одно наблюдение. Нижняя полоса формулирует следующее
решение. Укрупнение до трёх направлений не заменяет исходные четыре группы рубрики.

**Дальнейшее развитие.** Новые композиции реализовывать по принятому конвейеру
на подходящих данных; проверять читаемость и соответствие источникам до включения
в автоматическую библиотеку. Отдельные числовые макеты требуют вымышленных
примеров и не получают данные ради заполнения формы.
