задачи, выбрать шаблоны и подготовить проверяемый результат.

## Библиотека и оформление

Сначала выберите вопрос читателя и основания, затем визуальное отношение,
геометрию формата и стиль. Управленческий шаблон не задаёт цвета и шрифты.

| Ресурс | Назначение |
|---|---|
| [Consulting Presentations](../skills/consulting-presentations/SKILL.md) | Процесс подготовки документов, PDF и презентаций; переносимость между проектами |
| [Пополняемый каталог](../skills/consulting-presentations/library/catalog.json) | 10 управленческих шаблонов, 15 композиций, происхождение и статус реализации |
| [Управленческие шаблоны](../skills/consulting-presentations/references/management-templates.md) | Паспорт инициативы, резюме, статус, готовность, роли и следующие решения |
| [Визуальные композиции](../skills/consulting-presentations/references/visual-patterns.md) | Сравнения, этапы, архитектура, дерево решений и другие отношения |
| [Геометрия форматов](../skills/consulting-presentations/assets/format-profiles.json) | Компоновка A4 и 16:9 без брендовых настроек |
| [Стилевые наложения](../skills/consulting-presentations/assets/styles/) | Палитра, шрифты и бренд: neutral и cinimex |
| [Cinimex Consulting](../templates/presentations/cinimex-consulting/README.md) | Фирменный эталон и отдельный конвейер презентаций для чтения |
| [Правила пополнения](../skills/consulting-presentations/references/library-workflow.md) | Как превратить референс в повторно используемый абстрактный приём |

Готовые исполняемые примеры и рецепты различаются в каталоге; подтверждение
одного формата не распространяется автоматически на другие.
`assess slides` использует базовый автоматический макет, reading-конвейер —
отдельные композиции Cinimex Consulting. Общие правила проверки сохраняются.

## Проверка перед передачей

Для конкретного результата следуйте [правилам отчёта](REPORT.md),
[КП](PROPOSAL.md) или [презентации](PRESENTATION.md). Общий порядок:
проверить источники и статус утверждений, прочитать извлечённый текст,
просмотреть каждую страницу или слайд, исправить дефекты и проверить манифест.
Автоматическая проверка не заменяет визуальный просмотр.

Обязательные команды и правила Git — в [AGENTS.md](../AGENTS.md) и
[разделе разработки](../README.md#разработка). Клиентские материалы хранятся
отдельно от общей базы; в `examples/` входят только вымышленные проекты.

## Страницы, которые собираются из источников

`uv run assess build` создаёт следующие файлы. Они остаются локально,
не коммитятся и правятся через YAML-источники, а не вручную.

| Результат | Содержимое |
|---|---|
| `docs/RUBRIC.md` | Рубрика человеческим языком: шкала, решения и опорные описания |
| `docs/COMPANY.md` | Профиль компании с источниками |
| `docs/PORTFOLIO.md` | Сводка оценок и повторяющихся пробелов |
| `docs/reports/<id>.md` | Страница отчёта об оценке |
| `docs/proposals/<id>.md` | Страница коммерческого предложения |
| `docs/assets/` | Сгенерированные фигуры в светлом и тёмном оформлении |

Оформление главной страницы находится отдельно, в
[docs/media/](media/README.md), и не пересобирается командой `assess build`.
