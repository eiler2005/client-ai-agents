# Общая база для презентаций, документов и PDF

[Consulting Presentations](../skills/consulting-presentations/SKILL.md) — переносимый
скилл подготовки клиентских и управленческих материалов. Он выбирает содержание
и визуальные отношения, адаптирует их к формату и накладывает независимый стиль.
Синимекс использует свой стиль; другие проекты могут выбирать собственный.
Вынос общей папки в самостоятельный репозиторий можно выполнить позднее.

| Независимый слой | Назначение |
|---|---|
| [10 управленческих шаблонов](../skills/consulting-presentations/references/management-templates.md) | Вопрос адресата, основания, решение, роль и следующий результат; варианты сверки оценок, ресурсов, готовности, контрактов ролей и улучшений |
| [15 визуальных композиций](../skills/consulting-presentations/references/visual-patterns.md) | Общие строки, оси, ворота, ID и цепочки; дополнительно карта покрытия, диагностическое дерево и аннотированные инструкции |

## Процесс проекта

До написания и компоновки нового или существенно изменённого материала:

**вопрос адресата → поиск в базе → управленческий шаблон → основания →
визуальное отношение → геометрия формата → отдельный стиль →
сборка → текст и визуальная проверка**.

Для первой встречи сохраняется [структура по слайдам](PRESENTATION_STRUCTURE.md):
задача клиента отделена от предложенного решения; содержание и резюме занимают
по одному слайду. В документе эти блоки становятся разделами. Короткий статус
использует M03. AC, DoR и DoD имеют явную область действия и не образуют
накопительную лестницу автоматически.

Существующие схемы и генераторы оценки/КП сохраняют приоритет в расчётах,
обязательных разделах, источниках и проверках. Факты Синимекс берутся из
`src/content/company.yaml`; вводные клиента — из `clients/<client-id>/`.
PDF-renderer оценки/КП этим изменением не переподключён к свободным профилям.
Рабочий [фирменный эталон](../templates/presentations/cinimex-consulting/README.md)
по-прежнему называется Cinimex Consulting; это стиль, отдельно от имени скилла.

## Использование и установка

    $consulting-presentations Подготовь материал первой встречи в Markdown.
    Сначала задача клиента и вопросы к согласованию, затем наш подход.
    Найди подходящие управленческие и визуальные шаблоны; стиль — Синимекс.

Папка `skills/consulting-presentations` устанавливается ссылкой или копией
в `~/.codex/skills/consulting-presentations`. При переносе репозитория обнови
цель ссылки. Если список навыков ещё не обновился, открой новую сессию;
явный путь к SKILL.md работает сразу.

    python3 skills/consulting-presentations/scripts/library.py search "статус"
    python3 skills/consulting-presentations/scripts/library.py search "диагностика" --kind visual
    python3 skills/consulting-presentations/scripts/library.py check

Поиск использует стандартную библиотеку Python. [Пополнение](../skills/consulting-presentations/references/library-workflow.md)
сначала отделяет управленческую логику, визуальное отношение и оформление.
Вариант существующего приёма не получает новый ID без нового вопроса или отношения.

## Собственные исполняемые образцы и независимость стиля

Три редактируемых слайда: этапы с воротами, статус с общим календарём,
сопоставление процессов. A4-пример переносит те же вымышленные основания в PDF
и Markdown. Один профиль геометрии и один набор условий применяются к обоим стилям:

    node skills/consulting-presentations/scripts/render_gallery.mjs --style cinimex --out output/consulting-themes/cinimex/slides
    uv run --group pdf python skills/consulting-presentations/scripts/render_document_example.py --style cinimex --out output/consulting-themes/cinimex/document

Повтори с `--style neutral` для нейтрального оформления. По умолчанию переносимый
скилл выбирает neutral; этот проект задаёт cinimex явно. `--style` также принимает
путь к новому JSON, `--format-profile` — отдельную геометрию.
Палитра и шрифты меняются без переписывания M/V-рецептов.

Для PPTX нужны Node.js и `@oai/artifact-tool`; нестандартный путь задаётся
через `CONSULTING_ARTIFACT_TOOL` (старое имя поддерживается для совместимости).
Для PDF нужны ReportLab, pypdf и кириллический шрифт. Замена шрифта записывается
в манифесте и требует нового просмотра. Выходные файлы и превью остаются вне Git.
DOCX-образец пока не реализован; его готовят через доступный скилл Documents.
Остальные композиции, включая V13–V15, пока представлены рецептами.

## Исходные примеры и границы проверки

В локальную [папку исходников](../reference-materials/README.md) скопированы все
пять файлов из Downloads/slides examples. SHA256 совпадает; оригиналы сохранены.
Полностью просмотрены 136 страниц/слайдов: 60 PDF и 76 PPTX. Постраничные реестры,
изображения и извлечённые сведения исключены из Git и защищены хуками.
Общая библиотека содержит только абстрактные приёмы и собственные образцы.

[Исследование](../skills/consulting-presentations/references/research.md) различает
первую выборку и полный разбор. Astra просмотрела все 60 страниц PDF; остальные
слайды разобраны основным агентом и отдельным рецензентом. Нативный PowerPoint
не открывался; ошибки импорта не считаются доказанными дефектами оригинала.
Полный обзор не является аудитом арифметики или достоверности утверждений источника.

В обоих стилях собраны и просмотрены по три слайда и три A4-страницы — 12 изображений.
Даты, роли, условия, неизвестное и решения совпадают между стилями и форматами.
PPTX сохраняет нативные объекты; шрифты не встроены. PDF проверен отдельно,
включая текст и кириллические глифы. Границы проверки описаны в
[review.md](../skills/consulting-presentations/references/review.md);
`verified_formats` в каталоге не распространяется на нереализованные рецепты.
