# Общая база для презентаций, документов и PDF

[Скилл Cinimex Consulting](../skills/cinimex-consulting/SKILL.md) — общий стандарт
подготовки клиентских и управленческих материалов. Он соединяет содержание,
визуальные отношения и стиль, затем адаптирует их к слайдам или странице документа.
Набор переносится отдельной папкой; он пригоден для других проектов с их вводными
и профилем компании. Вынос в самостоятельный репозиторий можно выполнить позднее.

| Общая часть | Назначение |

## Процесс проекта

Для нового или существенно изменяемого материала обращение к скиллу и базе
предшествует написанию и компоновке:

**вопрос адресата → поиск в базе → управленческий шаблон → основания →
визуальное отношение → компоновка выбранного формата → текст и визуальная проверка**.

Для презентации первой встречи сохраняется
[структура по слайдам](PRESENTATION_STRUCTURE.md): задача клиента отделена
от предложенного решения; содержание и резюме занимают по одному слайду.
В документе эти блоки становятся разделами. Короткий статус использует M03.
AC, DoR и DoD имеют явную область действия и не считаются накопительной лестницей.

Скилл дополняет существующие схемы и генераторы оценки/КП. Их расчёты, обязательные
разделы, источники и проверки сохраняют приоритет. Факты компании берутся из
src/content/company.yaml; реальные клиентские вводные — из clients/<client-id>/.
Document tokens служат исходным стилем новых свободных документов; существующий
PDF-renderer не переподключён к ним этим изменением.

## Использование и установка

    $cinimex-consulting Подготовь материал первой встречи в Markdown.
    Сначала опиши задачу клиента и вопросы к согласованию, затем наш подход.
    Найди подходящие управленческие и визуальные шаблоны в базе.

Для установки в локальный Codex используй папку skills/cinimex-consulting как
ссылку или копию в ~/.codex/skills/cinimex-consulting. Ссылка использует актуальную
базу репозитория. При будущем переносе обнови её цель. Если список навыков
не обновился в текущей сессии, открой новую; явный путь к SKILL.md работает сразу.

Поиск не требует зависимостей Python за пределами стандартной библиотеки:

    python3 skills/cinimex-consulting/scripts/library.py search "статус"
    python3 skills/cinimex-consulting/scripts/library.py search "ворота" --format document
    python3 skills/cinimex-consulting/scripts/library.py check

## Собственные исполняемые образцы

Три редактируемых слайда: этапы с воротами и свидетельствами, статус с прогнозом
и решением, сопоставление процессов. A4-пример переносит те же вымышленные
основания и решения в PDF и Markdown. Это примеры для сборки и разбора;
девять остальных визуальных композиций пока представлены рецептами. DOCX-образец
пока не реализован; его готовят через доступный скилл Documents.

    node skills/cinimex-consulting/scripts/render_gallery.mjs --out output/consulting-gallery
    uv run --group pdf python skills/cinimex-consulting/scripts/render_document_example.py --out output/consulting-document

Для PPTX нужны Node.js и @oai/artifact-tool; нестандартный путь — CINIMEX_ARTIFACT_TOOL.
Для PDF нужны ReportLab, pypdf и шрифт с кириллицей. Зависимости и параметры CLI
описаны в генераторах. Выходные файлы, превью и манифесты остаются вне Git.

## Исследование и границы проверки

[Исследование](../skills/cinimex-consulting/references/research.md) различает
фактически просмотренные фигуры и прочитанные материалы. Astra разобрала
управленческий смысл и визуальные связи пользовательских примеров и текущих слайдов;
официальные фигуры McKinsey, Bain, BCG и Accenture использованы для собственных
адаптаций. Исходные слайды, скриншоты и данные проектов в общую базу не включены.

Независимый прогон Astra на задаче с неполными вводными проверил выбор M/V,
различение плана и прогноза, сохранение неизвестного и условий решения. Он дал
текст и планы двух слайдов без рендера; визуальную проверку этого прогона
не заявляем. Правила передачи артефактов — [review.md](../skills/cinimex-consulting/references/review.md).
Проверенные форматы примеров отмечены отдельно в каталоге.
