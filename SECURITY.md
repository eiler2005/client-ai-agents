# Обращение с данными заказчиков

Репозиторий хранит общую методику, код и шаблоны. Реальные оценки, ТЗ и презентации
клиентов остаются в локальных папках. Файл оценки —
это описание того, где у заказчика слабые места в безопасности, данных и контроле.
Утечка такого файла хуже утечки обычной проектной документации.

## Что где лежит

| Что | Где | В git |
|---|---|---|
| Рубрика, код, шаблон, документация | `src/`, `docs/`, `templates/` | да |
| Вымышленные образцы | `examples/` | да |
| Материалы конкретного клиента | `clients/<client-id>/`, прежний `docs/client-projects/` | **нет** |
| Оценки по реальным проектам | `assessments/` | **нет** |
| Собранные отчёты, фигуры, манифесты | `dist/`, `docs/reports/`, `docs/assets/` | **нет** |

`.gitignore` и `.githooks/privacy-check` держат это разделение. Хук подключается
командой `git config core.hooksPath .githooks` и проверяет индекс перед каждым коммитом:
пути, расширения, приватные ключи, похожие на секреты строки и адреса электронной почты.
Хук `pre-push` дополнительно проверяет каждый новый коммит: клиентские файлы не
должны присутствовать даже в старых версиях отправляемой истории. Ветки `local/`
не публикуются. Общая база хранится с отдельной чистой историей; прежняя локальная
история с клиентскими материалами не отправляется на сервер.

## Правила заполнения оценки

- Роли, а не имена: «технический лид проекта», «руководитель информационной
  безопасности банка». Имена допустимы только для наших собственных сотрудников в поле
  `assessors`.
- Источник записывается как вид, название и дата. Содержимое внутренних документов
  заказчика в репозиторий не переносится.
- Ни учётных данных, ни внутренних адресов и имён хостов, ни идентификаторов тикетов,
  ни выгрузок с реальными данными клиентов заказчика.
- Найденная уязвимость описывается на уровне, достаточном для её исправления, и не
  содержит готовой инструкции по эксплуатации.

## Передача отчёта

Собранный PDF лежит в `dist/`, который не коммитится. Канал передачи согласуется с
заказчиком. Перед отправкой — проверки из [docs/REPORT.md](docs/REPORT.md), включая
поиск по тексту на имена и внутренние адреса.

Манифест рядом с PDF (контрольные суммы входных файлов и самого документа) кладётся в
архив проекта вместе с отправленным файлом: он позволяет позже доказать, какая именно
версия ушла заказчику.

## Если данные всё-таки попали в историю

Удаления файла следующим коммитом недостаточно — он остаётся в истории. Нужно
остановиться, не пушить, сообщить ведущему репозиторий и переписать историю
(`git filter-repo`) до того, как ветка уйдёт на удалённый сервер. Если уже ушла —
считать данные скомпрометированными и уведомить заказчика.

## Сообщить о проблеме

О найденной проблеме в самом инструменте или о возможной утечке — напрямую владельцу
репозитория, не через публичный issue.
