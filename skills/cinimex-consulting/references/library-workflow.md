# Пополняемая база управления и визуализации

[library/catalog.json](../library/catalog.json) — общий поисковый индекс.
Подробные рецепты живут в одном каноническом месте в `references/`; индекс
содержит вопрос, теги, необходимые вводные, связи M/V, источник и зрелость.
Параметры оформления общие, компоновка зависит от формата.

## Использование при создании материала

1. Найди вопрос/отношение по русским или английским тегам либо ID:
   `python3 <skill-dir>/scripts/library.py search "forecast"`.
2. Выбери M, затем V. Прочитай соответствующие разделы рецептов и ветку формата.
   Для простой мысли таблица или текст могут быть достаточны.
3. Сохрани основания, неизвестное и требуемое действие. Готовый пример помогает
   компоновке; его вымышленные сроки и решения не становятся данными нового проекта.
4. Проверь фактический результат. Если найден новый полезный приём, пополни базу
   отдельным общим изменением после его разбора.

## Как добавить пользовательский или исследованный пример

Сохрани оригинал, рабочие изображения и извлечённые сведения в локальной папке
проекта. В общей базе запиши источник: вид, нейтральное название и дату просмотра;
для публичного исследования также URL и номер фигуры/страницы. Укажи, просмотрено
ли само изображение. Прочитанная статья не доказывает визуальное качество её фигур.

Выдели два результата отдельно:

- **Управление:** вопрос адресата, решение, вводные, основания, принимающая роль,
  следующий проверяемый результат. Добавь M, только если меняется эта логика.
- **Визуал:** отношение и общий ключ, схема компоновки, ограничения применения,
  ошибки чтения и способ проверки. Добавь V, если найден новый полезный механизм.

Не создавай новый ID для каждой перестановки блоков. Добавь вариант к имеющемуся
рецепту, если вопрос и отношение те же. Для нового рецепта используй следующий
свободный M/V ID, сохраняя старые ID. Описание не переносит реальную архитектуру,
числа, цитаты из внутренних документов или личные данные. Образец придумывается
с нуля; обезличенный реальный проект не становится общим примером.

## Зрелость и проверка

Поля каталога имеют разный смысл:

| Поле | Значения и основание |
|---|---|
| `review_status` | `candidate` — предложенный приём; `reviewed` — проверены управленческий смысл и визуальное отношение |
| `implementation_status` | `recipe` — инструкция; `example` — есть исполняемый собственный образец |
| `formats` | Приём применим к `slides` и/или `document`; это не результат рендера |
| `example_scripts` | Пути генераторов по конкретным форматам: slides, pdf, markdown, docx |
| `verified_formats` | Форматы образца, в которых прочитан текст и просмотрен итоговый рендер; MD проверяется по тексту |
| `sources` | ID источников происхождения приёма; не подтверждают данные нового клиента |

Кандидат получает краткий рецепт и запись в индексе. После проверки смысловых
связей его статус становится `reviewed`. Если добавлен генератор, статус реализации
становится `example`; проверенные форматы отмечаются только после сборки и просмотра.
В манифесте конкретной сборки остаются дата, контрольные суммы и фактические проверки.
После изменения генератора, данных примера или общих tokens очисти затронутые
`verified_formats` до повторной сборки и проверки; старый просмотр не подтверждает
новую версию. Уже прочитанные неизменившиеся рецепты повторно искать не требуется.
Переименование поля или текстовая правка не требуют отдельного манифеста на абзац.

Выполни `python3 <skill-dir>/scripts/library.py check` после изменения индекса.
Для нового генератора проверь его собственный образец; для существенной правки
инструкций полезна независимая задача с неполными вводными. Затем обнови краткую
историю изменений проекта и коммить только общие инструкции, рецепты и код.

## Будущий перенос

Папка скилла переносится целиком: `SKILL.md`, `agents/`, `references/`, `library/`,
`assets/`, `scripts/`. Индекс и генераторы используют относительные пути внутри неё.
Профиль компании, материалы клиента, правила рубрики и зависимости среды остаются
в вызывающем проекте. Внешние навыки и runtime выбираются по доступности;
перенос не подразумевает копирование секретов или исходных клиентских документов.
