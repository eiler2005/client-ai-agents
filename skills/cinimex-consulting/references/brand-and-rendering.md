# Стиль и реализация

При явном пользовательском шаблоне сохраняй его оформление. Для проекта Синимекс
базовый стиль — Cinimex Consulting v2: тёмная предметная обложка и светлые
аналитические слайды. Параметры ниже перенесены из существующего эталона;
это рабочий стиль проекта, а не опубликованный полный брендбук.
Канонические параметры набора — [design-tokens.json](../assets/design-tokens.json).
Цвета общие для документов и слайдов; размеры и компоновка зависят от формата.

## Слайд 16:9

| Параметр | Значение |
|---|---|
| Холст | 1280×720, 16:9 |
| Шрифт | Calibri, кириллица |
| Основной текст | `#071D33` |
| Акцент | `#F28A20`; для небольших оранжевых надписей на светлом `#9B4F10` |
| Пояснения | `#536777` |
| Фон | `#FFFFFF` или `#F4F7FA` |
| Разделители | `#DDE5EB` |
| Поля | Обычно 56–72 px; одинаковые слева и справа |
| Основной текст для чтения | Предпочтительно 19–21 px; минимум эталона 17 px = 12,75 pt |
| Заголовок аналитического слайда | Обычно 31–37 px с учётом длины и эталона |
| Источник | Обычно 12 px = 9 pt |

Размеры в API с px не являются pt: 96 px = 72 pt. Пользовательский шаблон
приоритетен; без него выполняются требования используемого механизма презентаций.
Если Calibri недоступен, выбери доступный шрифт с кириллицей, отрази замену
и снова проверь переносы. Не молча имитируй шаблон похожими размерами.

Обложка содержит название проекта, заказчика, предложение Синимекс, дату/статус
и контакты из профиля компании. Собственная иллюстрация показывает предмет
работы; она обозначена концептуальной, если не подтверждает реальный объект.
Логотип используй из утверждённого проекта или предоставленного файла.
В наборе образцов логотип и факты компании не подменяются самодельными знаками.

Иерархия чтения: вывод → основное отношение/доказательство → объяснение и действие.
Оранжевый выделяет предмет решения; статус дополнительно подписан словом.
Неизвестное не окрашивается как успех. Декоративная панель не должна занимать
место доказательства. Плотный dashboard допустим для общего управленческого
вопроса, с общей датой среза и календарём; случайный набор панелей не считается им.

## PPTX и другие форматы

Маршрут и правила переноса — [format-adapters.md](format-adapters.md).
Для нового свободного документа исходные настройки: A4, поля 42 pt, основной
текст 11 pt / интерлиньяж 15 pt, заголовок раздела 15 pt, DejaVu Sans с кириллицей.
Параметры не заменяют стиль явно предоставленного документа или существующий
renderer отчётов/КП. Цвет и иерархия чтения общие, геометрия A4 перестраивается
в вертикальные разделы и таблицы с повторяемыми заголовками.

Для рабочего PowerPoint используй доступный скилл Presentations и поддерживаемый
им backend. В текущей среде это `@oai/artifact-tool` через ES modules. Для простых
схем — нативные текст, геометрия и connectors; для сложных самостоятельных схем
— подходящий механизм diagram-design. Декоративные изображения можно искать
или генерировать, но они не кодируют точные значения и границы полномочий.

Создавай соединения перед узлами, чтобы линии оказались позади них. Проверь
направления и окончания стрелок. При импорте чужого PPTX отдельно различай
ошибку исходного слайда и артефакт импорта: изменённый checkbox, потерянный
коннектор или placeholder не доказывают дефект первоначального оформления.

Нативные объекты сохраняют редактируемость. Цифровой график связывается с данными;
таблица — с сопоставимыми критериями; семантическая схема — с ролями и действиями.
Не растеризуй всю страницу для обхода проблем компоновки.

Генератор `scripts/render_gallery.mjs` создаёт три вымышленных образца и превью.
Для него нужен Node.js и установленный artifact-tool; при нестандартном размещении
задай `CINIMEX_ARTIFACT_TOOL` как путь к каталогу пакета. Выходной каталог задаётся
через `--out`; сам вызов примеров не производит клиентскую презентацию.
PNG, PPTX, исходные рисунки клиентов и манифесты хранятся вне общего Git.
Готовые шаблоны редактируются через источник генератора и проверяются после сборки.

`scripts/render_document_example.py` использует ReportLab и pypdf и создаёт
собственный A4 PDF и Markdown. Кириллические TTF можно передать через `--font-dir`;
доступные варианты и параметры смотри в `--help`. Проверка глифов предшествует
созданию PDF. PNG страниц готовится через доступный PDF renderer; весь итог
просматривается независимо от проверки слайдов.
