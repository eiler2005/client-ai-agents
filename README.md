# client-ai-agents — клиентские проекты ИИ-агентов Синимекс

Общая база Синимекс для подготовки и оценки клиентских проектов ИИ-агентов:
от понимания задачи и материала первой встречи до концепции решения, оценки
проекта, презентации и коммерческого предложения. Здесь собраны методика,
проверяемый профиль компании, код сборки документов и шаблоны оформления.

**Краткое описание для каталога проектов:** методика и инструменты Синимекс для
работы с клиентскими ИИ-проектами: понимание задачи, концепция решения, оценка,
презентации и КП. Общая база хранится в Git; материалы клиентов — в локальных
папках проектов.

| Карточка проекта | Описание |
|---|---|
| Название | `client-ai-agents` — клиентские проекты ИИ-агентов Синимекс |
| Задача | Согласовать потребность клиента, обосновать подход, определить пилот и критерии успеха, подготовить оценку и предложение |
| Пользователи | Команда клиентского проекта: руководитель, бизнес-аналитик, архитектор и специалисты по ИИ |
| Рабочие материалы | Концепция и ТЗ, презентация для чтения, отчёт об оценке и коммерческое предложение |
| Основа | Единая рубрика, факты о Синимекс с источниками, структура рассказа и стиль Cinimex Consulting |

Порядок работы: **задача клиента → сценарии и границы → предлагаемое решение →
пилот и приёмка → оценка и КП**. [Структура клиентской презентации по слайдам](docs/PRESENTATION_STRUCTURE.md)
задаёт состав материала для первой встречи и его связь с последующим ТЗ.

В GitHub публикуется общая база: код, методика, профиль Синимекс, стили и шаблоны.
Материалы реальных клиентов находятся в локальных папках
[`clients/<client-id>/`](clients/README.md) и исключены из Git, включая историю push.

Для автоматической сборки оценки и КП на входе — YAML-файлы: оценка проекта,
предложение и профиль компании. На выходе —
взвешенная оценка по рубрике, решение по проекту, страницы в `docs/` и два документа в
PDF, которые не стыдно отдать заказчику: отчёт об оценке и КП.

Инструмент не ставит оценку и не пишет предложение за вас. Он держит рамку: по чему
оцениваем, что считаем подтверждением, как из уровней получается решение, и какие
утверждения о Синимекс мы готовы защищать — каждое со своим источником и датой.

## Начало работы

```sh
uv sync --group dev --group pdf
uv run assess --demo build                      # фигуры и страницы по образцам
uv run assess --demo pdf --out dist/pdf-demo    # отчёт об оценке
uv run assess --demo proposal --out dist/kp-demo # коммерческое предложение
uv run assess --demo slides --only demo-retail-support
uv run assess --demo slides --kind proposal --only demo-retail-support-kp
```

Свой проект:

```sh
uv run assess new db-01-support                 # оценка из шаблона
uv run assess check                             # проверка по ходу заполнения
uv run assess score                             # балл и решение в терминале
uv run assess build                             # фигуры и страницы в docs/
uv run assess pdf --only db-01-support
uv run assess pdf --only db-01-support --brief  # версия на 4–6 страниц

uv run assess new db-01-support-kp --kind proposal
uv run assess proposal --only db-01-support-kp
uv run assess slides --only db-01-support
uv run assess slides --kind proposal --only db-01-support-kp
```

`assess company` показывает профиль компании и отмечает факты, которые пора обновить.

`assess slides` собирает редактируемый PowerPoint в `dist/slides/`, без пересборки
PDF и страниц. Нужны Node.js 22+ и пакет `@oai/artifact-tool` из среды Codex;
настройка и правила оформления описаны в [стандарте презентаций](docs/PRESENTATION.md).
Презентация оценки показывает решение, охват, зрелость, ключевые пробелы и план.
Презентация КП добавляет этапы, команду, условия и подтверждённый опыт компании.

## Как считается оценка

Двенадцать измерений в четырёх группах, у каждого свой вес. Уровень измерения — от 0
(практики нет) до 4 (измеряется и улучшается по данным) по опорным описаниям рубрики.
Уровень переводится в проценты и складывается с весами.

В расчёт входят **только оцененные измерения**: неоцененное не считается нулём, но
снижает охват. Черновик с половиной заполненных измерений честно показывает балл по
этой половине и рядом — охват.

Решение не выводится из средней напрямую. Три измерения помечены в рубрике как
блокирующие — **данные и знания**, **безопасность и ПДн**, **оценка качества и эвалы**.
Уровень 0–1 по любому из них опускает решение до «сначала закрыть пробелы», какой бы
высокой ни была средняя. В агентных проектах именно эти пробелы дороже всего закрывать
после запуска.

| Решение | Порог |
|---|---|
| Идём | 75 |
| Идём с условиями | 60 |
| Сначала закрыть пробелы | 40 |
| Не идём в текущем виде | 0 |

Расчётное решение можно переопределить вручную в `verdict.decision`, но расхождение
попадёт в вывод `assess check` — чтобы его объясняли, а не забывали.

## Коммерческое предложение

КП собирается из двух источников и ниоткуда больше: файл предложения в `proposals/`
описывает клиента, объём, этапы, команду и деньги; профиль компании даёт раздел
«О Синимекс».

Состав: титул, содержание, что предлагаем, понимание задачи, объём работ, как мы это
делаем, план и сроки, команда, риски, коммерческие условия, о компании, следующие шаги.

Раздел о компании — это и есть «реклама», но построенная на проверяемом: позиционирование,
цифры с источником и датой, корпоративная ИИ-платформа, подтверждённый опыт, подобранный
под отрасль клиента, и публично названные клиенты. Цифры эффекта всегда печатаются вместе
с оговоркой о том, что они получены на других проектах.

Если в `project.assessment` указан идентификатор оценки, раздел «Понимание задачи»
подтягивает из неё решение, пробелы и опору: заказчику видно, что предложение выросло
из обследования, а не из прайс-листа. Образец этой связки — в `examples/`.

Проверка не даст сослаться в КП на услугу, факт или кейс, которых нет в профиле
компании. Это главное, ради чего профиль существует: в предложении не появится цифра,
за которую некому отвечать.

## Отчёт

A4, 11 пунктов, колонтитул с пометкой конфиденциальности, закладки по разделам.
Оглавление не угадывает страницы: документ печатается, из его закладок читаются номера,
оглавление пересобирается и печатается снова, пока номера не сойдутся.

Рядом с PDF пишется манифест: контрольные суммы входных файлов, шрифтов и фигур, число
страниц, sha256 самого файла. Через полгода по нему видно, из чего собран тот файл,
который ушёл заказчику.

## Конфиденциальность

Оценки и предложения содержат данные клиентов и коммерческие условия. Правила, которые
держит репозиторий:

- `clients/<client-id>/`, старый `docs/client-projects/`, `assessments/` и `proposals/`
  не коммитятся — в `.gitignore` пропущены только общие README
  и `.gitkeep`;
- `dist/`, PDF, PNG и собранные страницы тоже не коммитятся;
- в файлах пишутся роли, а не имена сотрудников заказчика;
- `.githooks/privacy-check` проверяет индекс перед коммитом, а `pre-push` — все новые
  коммиты и отсутствие локальных веток. Хуки подключаются одной командой:

```sh
git config core.hooksPath .githooks
```

В репозиторий коммитятся: рубрика, профиль компании, код, шаблоны, документация и
вымышленные образцы.
